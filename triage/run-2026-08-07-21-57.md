FINDING 1: CORS reflect-any-origin with credentials on api.sparelabs.com /v1/
════════════════════════════════════════════════════════════════════════
Source models: bigpickle (conf 50→80), laguna (conf 95), nemotron3 (conf 95)
Class: MISCONFIG (Improper Configuration / CORS)
Asset: api.sparelabs.com /v1/**  [In scope per scope.yml]

Probe evidence (passive, GET/HEAD):
  OPTIONS /v1/journeys + Origin: https://evil.example.com
    -> 204, access-control-allow-origin: evil.example.com
    -> access-control-allow-credentials: true
    -> access-control-allow-methods: GET,HEAD,PUT,PATCH,POST,DELETE
    -> access-control-allow-headers: Authorization
  GET /v1/journeys + Origin: evil.example.com (no auth) -> 401,
    body echoes ACAO+ACAC on auth-gated route.
  GET /v1/global/organizations + Origin -> 200 + reflected ACAO+ACAC.
  GET /v1/public/terms + Origin -> 200 + reflected ACAO+ACAC.
  404 path + Origin -> NO ACAO (middleware scoped to real API surface).

7-Question Gate:
  Q1 In scope?           YES — api.sparelabs.com is in scope.
  Q2 Attacker-reachable? YES — public OPTIONS/GET, no auth needed to observe.
  Q3 Real impact?        YES — any malicious origin can drive credentialed
                                cross-origin read+write (all methods, incl.
                                Authorization header) IF a victim's browser
                                auto-attaches credentials. Bearer-only
                                observed today; standalone impact is a
                                force-multiplier for any XSS and an OWASP
                                A05:2021 misconfig. Escalates to CRITICAL if
                                any cookie/client-cert auth appears.
  Q4 Provable passive?   YES — OPTIONS preflight + GET with arbitrary Origin
                                headers; no payloads, no writes.
  Q5 Novel?              YES — no prior report on file for this asset.
  Q6 Not rejected-list?  YES — this is a real CORS trust-boundary failure,
                                not a "best practice" gripe. Confirmed header
                                reflection with credentials.
  Q7 Reasonable triager? YES — multiple independent models (3/5) converged
                                on the same header-level evidence.

Verdict: VALID — report as MEDIUM (force-multiplier misconfig);
         note escalation path to CRITICAL if any auto-attached credential
         (cookie, client cert, basic auth) is ever observed on any /v1 route.

Minimal read-only proof steps:
  1. curl -s -D - -o /dev/null -X OPTIONS \
       -H "Origin: https://evil.example.com" \
       -H "Access-Control-Request-Method: POST" \
       -H "Access-Control-Request-Headers: Authorization" \
       https://api.sparelabs.com/v1/journeys
  2. curl -s -D - -o /dev/null -X GET \
       -H "Origin: https://evil.example.com" \
       https://api.sparelabs.com/v1/global/organizations
  3. Observe ACAO echoes attacker Origin + ACAC: true in both.
  Impact: Cross-origin read/write of API responses for any victim whose
    browser auto-attaches credentials; with Bearer-only auth today this is
    a cross-origin authorization bypass amplifying any future XSS and
    enabling cross-origin mutation if a credential-auto-attach path exists.
CVSS 3.1: 7.5 (CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:N) —
    HIGH if cookie/client-cert path confirmed; stays MEDIUM as standalone.
Reporting channel: Spare bug-bounty program channel (per scope.yml:
    "TBD - operator-provided program scope"; disclose via the program's
    designated intake once confirmed — do NOT pre-disclose).
