## LEAD 1: CORS reflect-any-origin + credentials on api.sparelabs.com /v1/**

| Q | Answer |
|---|---|
| Q1 In scope? | **YES** — api.sparelabs.com is in-scope. |
| Q2 Attacker-reachable? | **YES** — entire /v1 surface is public at the edge. |
| Q3 Real impact? | **YES** — any site can drive credentialed cross-origin calls. Practical exploit requires auto-attached credentials (cookies). Bearer-only observed today. |
| Q4 Passive-proof? | **YES** — OPTIONS + GET with `Origin: https://evil.example.com` captured `ACAO: evil.example.com` + `ACAC: true` on /v1/journeys, /v1/global/organizations, /v1/public/terms. |
| Q5 Novel? | **YES** — not previously reported to Spare. |
| Q6 Not rejected? | **YES** — real A05:2021 misconfig, not best-practice noise. |
| Q7 Reasonable triager? | **YES** — confirmed by 3 models across 5+ time samples. |

**Verdict: VALID — CVSS 5.3 (Medium)**

Vector: `CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:L/I:N/A:N` — capped at Medium
because no Set-Cookie / auto-attached credential observed on any /v1 route.
Severity escalates to **High 8.2** (`AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:N/A:N`)
the moment any cookie-based session is found.

Minimal read-only proof:
```
curl -s -X OPTIONS -H "Origin: https://evil.example.com" \
     -H "Access-Control-Request-Method: GET" \
     -H "Access-Control-Request-Headers: Authorization" \
     https://api.sparelabs.com/v1/journeys -D - -o /dev/null
curl -s -H "Origin: https://evil.example.com" \
     https://api.sparelabs.com/v1/global/organizations -D - -o /dev/null
```
Expected: `access-control-allow-origin: https://evil.example.com`,
`access-control-allow-credentials: true`, `vary: Origin` on every /v1 path.

Impact: Any malicious page can issue cross-origin requests that the browser
sends to the API with the victim's origin reflected and credentials
accepted. If the victim has an auto-attached credential (cookie), the
attacker reads the JSON response — rider/org/journey data. With write
methods (PUT/PATCH/POST/DELETE all allowed in preflight ACAM), the same
vector mutates state. Today Bearer-only, so exploit requires a cookie-auth
route; report as Medium with escalation note.

Reporting channel: **Spare security channel per scope.yml
(`disclosure_policy: TBD` — operator to confirm).**

| Q7 Reasonable triager? | **YES** — confirmed stable pattern, not flapping. |

**Verdict: VALID — CVSS 5.3 (Medium)**

Vector: `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N`

Minimal read-only proof:
```
curl -s https://api.sparelabs.com/v1/global/organizations            # 200
curl -s "https://api.sparelabs.com/v1/global/organizations?limit=50" # 200 same body
```

gap) could expose a data-bearing sibling (/v1/global/settings,
/v1/global/regions, etc.). Combined with Lead 1's credential CORS, a
malicious origin reads whatever the fail-open route returns — exploit
amplifier.
