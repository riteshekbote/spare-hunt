## LEAD 1: CORS reflect-any-origin + credentials on api.sparelabs.com /v1/**

| Q | Answer |
|---|---|
| Q1 In scope? | **YES** — api.sparelabs.com is in-scope. |
| Q2 Attacker-reachable? | **YES** — entire /v1 surface is public at the edge. |
| Q3 Real impact? | **YES** — any site can drive credentialed cross-origin calls. Bearer-only observed today; exploit requires auto-attached credentials (cookies). Write methods (PUT/PATCH/POST/DELETE) all allowed in preflight ACAM. |
| Q4 Passive-proof? | **YES** — OPTIONS + GET with `Origin: https://evil.example.com` captured `ACAO: evil.example.com` + `ACAC: true` on /v1/journeys, /v1/journeys/requests, /v1/global/organizations, /v1/public/terms — stable across 4 models and 10+ time samples (18:31 UTC → 01:02 UTC). |
| Q5 Novel? | **YES** — not previously reported to Spare; confirmed stable (not path-conditional) across all scan intervals. |
| Q6 Not rejected? | **YES** — real A05:2021 misconfig, not best-practice noise. |
| Q7 Reasonable triager? | **YES** — confirmed by all 5 models; 95 confidence consensus. |

**Verdict: VALID — CVSS 5.3 (Medium)**

Vector: `CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:L/I:N/A:N`

Severity escalates to **High 8.2** (`AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:N/A:N`)
the moment any cookie-based session or auto-attached credential exists on
any /v1 route.

Minimal read-only proof:
```
curl -s -X OPTIONS -H "Origin: https://evil.example.com" \
     -H "Access-Control-Request-Method: GET" \
     -H "Access-Control-Request-Headers: Authorization" \
     https://api.sparelabs.com/v1/journeys/requests -D - -o /dev/null
curl -s -H "Origin: https://evil.example.com" \
     https://api.sparelabs.com/v1/global/organizations -D - -o /dev/null
```
Expected: `access-control-allow-origin: https://evil.example.com`,
`access-control-allow-credentials: true`, `access-control-allow-methods:
GET,HEAD,PUT,PATCH,POST,DELETE`, `vary: Origin` on every /v1 path.

Impact: Any malicious page can issue cross-origin requests that the browser
sends to the API with the victim's origin reflected and credentials
accepted. If the victim has an auto-attached credential (cookie), the
attacker reads the JSON response — rider/org/journey data. Write methods
(PUT/PATCH/POST/DELETE all allowed in preflight ACAM) let the same vector
mutate state. Today Bearer-only; report as Medium with escalation note.

Reporting channel: **Spare security channel per scope.yml
(`disclosure_policy: TBD` — operator to confirm).**

## LEAD 2: Organizations controller-wide auth omission on /v1/global/organizations

| Q | Answer |
|---|---|
| Q1 In scope? | **YES** — api.sparelabs.com is in-scope. |
| Q2 Attacker-reachable? | **YES** — no auth header required on GET list, GET {uuid}, GET key/{key}, GET {uuid}/mobileApps, GET zones/centroid. |
| Q3 Real impact? | **YES** — returns 200 (list, empty data), 400 (subroutes with validation errors), 404 (non-existent UUIDs) — all WITHOUT `InvalidTokenError`, proving auth middleware is omitted on the entire controller, not one route. Siblings (/v1/global/settings, /v1/global/regions, /v1/journeys/requests) correctly 401/400. Combined with Lead 1's credential CORS, a malicious origin reads whatever the fail-open controller returns. |
| Q4 Passive-proof? | **YES** — differential captured live: list→200, {uuid}→404, key/{key}→404, {uuid}/mobileApps→400, zones/centroid→400 — all WITHOUT InvalidTokenError. Control: /v1/journeys/requests→401 InvalidTokenError. 6+ consecutive 200s across ~2h including ?limit=&offset= variants (params ignored, hardcoded 11B body). |
| Q5 Novel? | **YES** — upgraded from "route-level" to "controller-wide" scope; the broadened impact is newly confirmed. |
| Q6 Not rejected? | **YES** — genuine auth-gate omission, not noise. |
| Q7 Reasonable triager? | **YES** — stable pattern confirmed across 4 models; bigpickle 75 confidence. |

**Verdict: VALID — CVSS 5.3 (Medium)**

Vector: `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N`

Promoted from prior report: previously scored as "route-level auth
omission"; new evidence confirms the omission covers the entire
organizations controller (list + all probed subroutes answer without
`InvalidTokenError`). Severity remains capped while the list payload is
empty (`{"data":[]}`), but the same middleware gap could expose a
data-bearing sibling at any time.

Minimal read-only proof:
```
curl -s https://api.sparelabs.com/v1/global/organizations                        # 200 {"data":[]}
curl -s "https://api.sparelabs.com/v1/global/organizations?limit=50&offset=0"    # 200 same body
curl -s https://api.sparelabs.com/v1/global/organizations/00000000-0000-0000-0000-000000000000  # 404
curl -s https://api.sparelabs.com/v1/journeys/requests                           # 401 InvalidTokenError (control)
```

Impact: Unauthenticated access outside the intended /v1/public/*
namespace; org-registry existence oracle by UUID+key. Currently empty
payload caps severity. Same root cause (per-controller middleware gap)
could expose a data-bearing sibling (/v1/global/settings,
/v1/global/regions). **Composed with Lead 1's credential CORS, a
malicious origin reads whatever the fail-open controller returns —
exploit amplifier. Report Leads 1 + 2 together as a chained finding.**

Reporting channel: **Spare security channel (TBD).**
