Subject: RE: Security Report — Unauthenticated Authentication-Bypass & Sensitive Credential Disclosure on api.sparelabs.com — Deep-dive addendum to Finding 2

Hello Spare Labs Security Team,

This is a follow-up expanding **Finding 2** (WorkOS SSO endpoint) from my report earlier today. The new material below was not part of the original submission — deeper testing on the same endpoint surfaced additional disclosures: partner Entra ID tenant GUIDs and the contents of the signed relayState JWT. I am sending this as an addendum so your team can track both under the same case.

Host: api.sparelabs.com
Endpoint: POST /v1/identity/workos/auth
Severity: Medium (CVSS 3.1: 5.3 — AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N)
Category: Authentication issue — missing authorization / information disclosure

--------------------------------------------------------------------
1. SUMMARY
--------------------------------------------------------------------
Beyond the client_id/connection_id disclosure already reported, the endpoint enables an unauthenticated caller to:
- Enumerate every SSO-integrated tenant (keyed lookup confirmed via controls),
- Walk the returned authorizationUrl to capture each partner's real Entra ID (Azure AD) tenant GUID,
- Decode the relayState JWT embedded in that URL, disclosing internal identifiers: saml_session_id, redirect_uri, and environment_id.

--------------------------------------------------------------------
2. ADDITIONAL REPRODUCTION
--------------------------------------------------------------------

  curl -s -X POST -H "Content-Type: application/json" -d "{\"domain\":\"$d\"}" \
    https://api.sparelabs.com/v1/identity/workos/auth; echo; sleep 0.7

--------------------------------------------------------------------
3. IMPACT (honest assessment)
--------------------------------------------------------------------
Disclosed WITHOUT authentication, demonstrated above:
- Internal WorkOS client_id + per-tenant connection IDs
- Partner Entra ID tenant GUIDs (via first redirect hop)
- Internal deployment identifiers (environment_id, saml_session_id, callback path)
- Complete map of which agencies use SAML vs Google OAuth

NOT demonstrated / not claimed: account takeover, session theft, credential access,
code execution, or access to any third-party account data. The platform callback
(platform.sparelabs.com/workos/callback) correctly rejects unauthenticated requests
(401 InvalidTokenError). Phishing potential of minted genuine login URLs is noted as
context only, consistent with the original report.

--------------------------------------------------------------------
4. REMEDIATION ADDENDUM
--------------------------------------------------------------------
In addition to the fixes in the original report:
- Treat Entra tenant GUIDs and relayState JWT contents as sensitive; the authorization
  flow should not require the client to traverse a URL that embeds them where avoidable
  (WorkOS supports server-side handling of the redirect chain).
- Consider opaque, single-use handles in place of structured JWTs in RelayState.

--------------------------------------------------------------------
5. TEST HYGIENE
--------------------------------------------------------------------
Read-only GET/POST requests against api.sparelabs.com only; no accounts created, no
data modified, no login flows completed, manual testing at <=1 rps per program rules.
Probe domains were Spare-owned, partners' own public domains, or dummy controls.
